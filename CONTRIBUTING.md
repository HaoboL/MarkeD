# Contributing to MarkeD

Code contributions and proposals for Agent/Skill artifacts are welcome for review. The first round of third-party artifact review is limited to complete, single-license MIT or Apache-2.0 packages. CC0, mixed-license, GPL, and other licenses remain outside that scope. A PR is a proposal, not admission: the initial source checkout contains only MarkeD-owned example content and no populated runtime catalog. Third-party content is not added to the MarkeD-distributed catalog or routed by MarkeD to users until named manual review and the external report/appeal process are operational. There is no website submission portal, automatic content approval, or payment flow. A public repository or a manifest license string alone does not establish redistribution rights.

## Artifact format

Put each Agent or Skill in its own directory. Include `artifact.json`, one main file (`agent.md` or `SKILL.md`), a root `LICENSE`, `LICENSE.txt`, or `LICENSE.md`, and every required supporting script, reference, asset, and applicable upstream NOTICE file. List every support file, including license and NOTICE, explicitly in `support_files`. The manifest needs `id`, `version`, `kind`, `title`, `description`, `author`, `license`, `source`, and `content_file`; optional fields include `tags`, `stages`, `harnesses`, and `compatible_agents`. The `license` value must be exactly `MIT` or `Apache-2.0` for first-round admission. See `examples/` for the local format. Use a new version when any package file or license changes; imported versions are immutable.

When proposing content, give the original source URL and fixed revision, the author or rights holder, your basis for submitting it, the exact license and whether upstream contains a NOTICE file, any changes to upstream files, all required tools or permissions, and a full file list with hashes. Submit only content you have the right to share. Do not include private prompts, user conversations, model outputs, credentials, or personal data. A reviewer must compare the full package with upstream, retain copyright/attribution and applicable NOTICE text, check changed-file notices for Apache-2.0, and inspect instructions and scripts before approval. A review record is an operator attestation, not a legal or quality certification.

Local flow: `import` creates a pending entry; `review` records the named operator and evidence for the exact package hash; `admit` accepts that reviewed version into a local catalog; `rollout` separately makes it eligible for a task type and host. For Apache-2.0, the approving reviewer must add `--notice-checked` after checking whether upstream has a NOTICE and whether the package preserves it. The importer admits no content automatically. Rejection and pause remain auditable. The project does not automatically execute or install an artifact's scripts.

## Contribution and complaint path

Propose a new artifact or version in a PR using [the PR template](.github/PULL_REQUEST_TEMPLATE.md). The PR itself is the traceable submission; maintainers should record `pending`, `needs information`, `rejected`, `locally admitted`, `paused`, or `withdrawn`, with a reason and exact package hash. A correction changes the package version and receives a new review. Admission does not automatically enable a rollout, award points, or imply quality.

For a concern supported by public evidence, use the [content report template](.github/ISSUE_TEMPLATE/content-report.md); contributors can use the [appeal or withdrawal template](.github/ISSUE_TEMPLATE/content-appeal.md). Maintainers should pause affected routing/downloads when warranted, investigate and record a reason, preserve the historical audit, and let the contributor respond or submit a corrected version. A withdrawal request is reviewed and recorded; it does not erase prior public Git history or retroactively remove already downloaded copies. **Do not put private prompts, conversations, credentials, unpublished work or personal data in a public issue or PR.** If no private reporting contact is listed, do not send sensitive details. External third-party admission remains closed until that channel and its handling process are in place. No response-time promise or quality certification is offered.

MarkeD-owned code and its four original `1.0.1` examples use MIT. Contributed artifacts keep their own valid licenses and required attribution; the platform's MIT license does not relicense them. Machine checks look for a declared MIT/Apache-2.0 license and a plausible bundled license text, but do not prove the text is complete or rights are valid. Contributor points are currently nonredeemable local records, with no exchange or payment promise.
